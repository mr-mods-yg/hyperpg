## Confirmed findings

- With no conditions, the filter panel showed three actions without explaining what to add. In a two-condition Between/NULL example, the controls had accessible names but no visible field labels or condition grouping. At 390 × 600 with the 18 px setting, a long column name caused controls to extend beyond the visible panel. See `/tmp/hyperpg-further-design/baseline/light-desktop-filter-empty.png`, `light-desktop-filter-multi.png`, and `light-narrow-filter-multi.png`.
- Applying a changed filter by keyboard replaced the grid and left focus on `BODY` while the page reloaded. The failure was reproduced after the visual changes and before recovery was added: `/tmp/hyperpg-further-design/baseline/light-desktop-filter-error.png`.
- A long unbroken database name in history ran into the delete action at desktop and narrow sizes. SQL was visually truncated, and the row had no explicit keyboard focus styling of its own. See `/tmp/hyperpg-further-design/baseline/light-desktop-history-list.png`, `light-narrow-history-list.png`, `light-narrow-history-empty.png`, and `light-narrow-history-no-match.png`.

## Changes

- The filter builder now explains its empty state and that all conditions must match, groups and numbers conditions, and labels column, operator, and value fields visibly. Between has separate start/end labels; NULL operators retain their existing no-value behavior. Long selects and inputs can shrink and wrap within the panel; the selected column's full name is available in its title. Removing a condition returns focus to Add condition.
- Applying or resetting a changed query moves focus to the existing named table workspace while the grid is replaced. The unsaved-changes dialog returns focus there if the user discards and continues; a later response does not pull focus from a control the user has since chosen. If a builder-applied query fails after the grid is removed, the same builder reappears with its values and columns so the query can be corrected, retried, or reset. Recovery columns are kept per table tab. The existing error remains visible. Filter operators, query payloads, sorting and reset semantics are unchanged.
- History constrains long SQL and database text within the open action, reserves space for delete, and puts database and execution details on separate lines. Full SQL and database text remain in the DOM and in titles. The row has a visible focus state. Deleting returns focus to the next or previous visible delete action, or to search for the final item; clearing returns focus to search. The list can shrink and scroll while the search and actions remain available.

## Scope and remaining limits

At 390 × 600 with 18 px text, multiple filter conditions require vertical workspace scrolling; this was exercised rather than claiming that the entire builder fits at once. SQL previews remain visually truncated, with the full script available by opening the entry; database names now wrap in full after the parent refinement described below. Recovery was exercised for queries submitted through the filter builder; other database failure paths were not exhaustively audited. Native desktop rendering, real databases, assistive technology, and comprehensive contrast testing remain outside this pass. The export panel was not changed because this follow-up did not establish a related export defect.

## Reset review findings and fixes

The interrupted Terra Max review saved [a report](design-audit-follow-up-review.md) with two reproduced Reset findings. The parent addressed both: failed empty queries submitted through Reset or removing the final condition now retain the recovery builder, and Reset waits for the guarded operation to be accepted before changing the local draft. Cancelling Keep editing therefore preserves both the condition draft and unsaved row edits. Accepted Reset still clears the query, including an unapplied draft while no filter is active.

The new regression checks cover failed Reset, retrying an unchanged empty query, correcting it with a filter, removing the last condition, accepted Reset, and cancelling a guarded Reset with a draft value that differs from the applied value. These plus the existing rejected-filter, transient-retry and cross-tab recovery tests passed **5/5** (`/tmp/hyperpg-further-design/reset-fix.log`). The production build passed after the fixes. The earlier 82/82 full suite predates these two small fixes and is not presented as an 84-test post-fix run. The review provider hit a usage limit before final handoff; its saved findings and test evidence remain valid, and the subsequent focused recheck approved the fixes, as recorded in the completed outcome above.
