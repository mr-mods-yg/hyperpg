# Independent design audit — round 3

## Verdict

The original expanded-results pointer blocker is fixed, but the seven-category goal is **not met**. This focused re-audit found a separate, verified mobile keyboard blocker: opening navigation with Enter and then pressing Tab puts focus on an obscured background control; Enter can activate it. The finding exists in the normal SQL state as well as the expanded-results entry path, so it is not attributed to the one-condition fix. It was not identified in the broad Round 2 review. Scores use the unchanged rubric in `docs/design-audit.md`: 9 means polished and consistent inspected states, accessible critical controls, and no verified material issue; it is not universal assistive-technology or device certification.

## Remaining verified blocker

**High — keyboard focus and activation pass behind the open mobile drawer.** At 390 × 600 with 18 px text, run a SQL query in Light, focus **Open navigation**, and press Enter. Press Tab once: focus is on **New SQL script** at `(67.4, 8, 97.6, 48)`, entirely behind the drawer in the capture; its center hits the Connections heading rather than the focused button. Further forward Tabs in the inspected sequence focus other covered workspace controls. The browser reports an outline on those buttons, but the screenshot shows no visible focus because the drawer covers them. Pressing Escape while the covered New SQL button is focused leaves the drawer open; pressing Enter activates that background button, creates and selects Script 2, and closes the drawer. The same initial forward-Tab behavior was observed after opening navigation from expanded results. Starting again at the navigation trigger, Shift+Tab reaches the scrim and then Settings; Enter opens Settings and Escape closes the dialog and returns focus to the visible navigation trigger. Thus Settings is not wholly keyboard-inaccessible, but the ordinary forward path presents invisible focus and can invoke an unintended workspace action.

Reproduction evidence: `/tmp/hyperpg-design-audit/independent-round-3/keyboard-obscured-focus.png`, `keyboard-obscured-activated.png`, `keyboard-obscured.json`, and `keyboard-path.json`. Give the open drawer a coherent keyboard path that prevents focus and activation on obscured background controls, provides a discoverable way to close it, and returns focus sensibly. Recheck normal and expanded SQL entry, forward/reverse Tab, Escape, Settings activation, scrim close and repeat cycles. No other material blocker was verified in this focused pass.
